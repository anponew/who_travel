# Who Travel

Локальный планировщик поездок на Next.js, React и TypeScript. Данные и документы сохраняются в IndexedDB браузера. Без аккаунтов, облачной базы и демонстрационных поездок.

## Запуск в WebStorm

Открой терминал в папке проекта:

```sh
npm install
npm run dev
```

Адрес: http://127.0.0.1:3000. Оставь терминал открытым. Остановка: Ctrl+C. В следующий раз достаточно `npm run dev`. Node.js 22 LTS или новее. Если системный npm cache недоступен: `npm install --cache /private/tmp/who-travel-npm-cache`.

Для production-сборки: `npm run build`, затем `npm start`. Локальный dev использует Webpack с polling, поскольку файловый watcher Turbopack в ограниченном окружении macOS выдавал FSEvents error.

## Возможности

- Создание поездки сразу с городами и датами приезда/выезда. Новая поездка открывается на первом дне. «Настроить поездку» меняет название, даты и города.
- Общая дата выезда из одного города и приезда в другой разрешена. В один день можно посетить несколько городов, ночь считается один раз. Последний день поездки не добавляет ночёвку.
- Места, необязательное время, описание, ссылки, перетаскивание и назначение на день. Обычное место в плане удаляется насовсем с подтверждением. Для новых идей сохраняется происхождение: после назначения на день их можно вернуть в подборку. В подборке есть отдельное удаление навсегда.
- Идеи всей поездки. Отдельный раздел «Еда», сгруппированный по городам. Нераспределённые идеи и еду можно добавить в выбранный день.
- Отели с периодом `[заезд, выезд)`, адресом и отдельными ссылками на сайт и карту. Автоматическое назначение ночёвок, ручная замена конкретной ночи. Ваучер загружается один раз и доступен из связанных ночёвок.
- Карточка отеля показывает фактические назначенные ночи: количество и диапазон дат, например «7 ночей · 20–27 ноября». Если ручные замены разбили период, перечисляются отдельные диапазоны.
- Перелёты, поезда, автобусы и другие переезды внутри дня и в «Обзоре поездки». Если транспорт не указан, подпись — «Переезд». Дата отправления берётся из выбранного дня, отдельно указывается необязательное время. Прибытие вводится как местные дата и время, без конвертации часовых поясов.
- Несколько редактируемых заметок на день.
- PDF, PNG, JPEG, WebP, GIF до 20 МБ: выбрать → сохранить → открыть из карточки. В IndexedDB сохраняется сам Blob файла. Обычные сохранения происходят без всплывающего уведомления.
- Удаление поездки в её карточке, с подтверждением. Раздел «Данные и доступ» больше не дублирует список удаления.

## Карты и маршруты

Встроенной карты нет. Координаты вводить не нужно. Поле «Ссылка на карту» принимает Google Maps (включая короткие ссылки), Яндекс Карты, 2ГИС, OpenStreetMap и Apple Maps. «Показать на карте» отображается только при заполненной корректной ссылке именно в этом поле; сайт отеля не используется как карта. Существующие корректные map-ссылки из старого общего поля распознаются для совместимости.

У дня с двумя и более местами со ссылками на карты есть кнопка маршрута в Google Maps. Порядок берётся из плана. Для короткой ссылки, из которой нельзя получить поисковый запрос, используются название места и город; координаты и адреса автоматически не извлекаются. Google может распознать название неоднозначно — точки стоит уточнить после открытия.

Маршруты используют официальный формат [Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started), без API-ключа. Ссылки ограничены 2048 символами. Не более трёх промежуточных точек на часть, чтобы учитывать ограничения мобильных браузеров; части имеют общую точку перехода. Политика и интерфейс Google могут меняться.

## Выгрузка друзьям

«Поделиться маршрутом»:

- HTML для просмотра: фильтр по городам, цветная лента дней с переходом к нужной дате и дни списком. Внутри дня — локации и маршрут Google Maps, переезды и ночёвка. Кафе, назначенное на день, входит в общий порядок его плана и маршрута Google Maps с меткой «Еда». Кафе без назначенного дня остаются в подборке города «Где поесть». Под лентой дней чипсы «Маршрут» и «Где поесть» переключают содержимое выбранного города; без JavaScript это обычные ссылки к разделам. Нераспределённые кафе/рестораны доступны в «Где поесть» по городам; назначенные на день кафе туда не дублируются. Нераспределённые идеи размещены рядом с планом соответствующего города. На телефоне боковые блоки идут ниже. Нет общего маршрута всей поездки, глобальных чипсов «Еда/Идеи» и отметок посещения.
- JSON для редактирования: получатель загружает его через «Импортировать маршрут». Добавляется отдельная копия с новыми идентификаторами.

Документы и заметки дня в выгрузки не включаются. Данные переездов (направление, тип, номер, время) входят, их заметки в JSON очищаются. Описания мест, даты, адреса и названия отелей входят — перед отправкой проверь, нет ли в описаниях личного текста. Ничего автоматически не публикуется, синхронизации между копиями нет.

HTML работает как обычный локальный файл без установки приложения. Интернет нужен только для открытия внешних карт/сайтов. JavaScript используется для фильтра городов; без него все дни остаются видимыми. Документы не встраиваются в HTML.

## Хранение

Перезапуск компьютера/браузера не удаляет данные. Очистка данных сайта, приватный режим или автоматическое освобождение места браузером могут их удалить. Другой порт, hostname (`localhost` вместо `127.0.0.1`) или устройство имеют отдельное хранилище.

Локальное хранение не является зашифрованным хранилищем и не защищает от человека с доступом к профилю браузера. Приложение не отправляет поездки или документы на сервер. Внешние карты открываются только по действию пользователя.

Ключи и переменные окружения для текущей версии не требуются. Supabase и Mapbox не используются. Для размещения на GitHub Pages подготовлена статическая сборка; аккаунты пользователей приложения не нужны. Публикация не выполнялась.

## Проверки для самостоятельного запуска

```sh
npm run typecheck
npm test
npm run build
```

Браузерные сценарии находятся в `tests/browser`; они были написаны до последних изменений интерфейса и требуют актуализации. В ограниченном окружении предыдущий запуск Chromium завершался до открытия страницы (SIGABRT).

Проверка типов и статическая сборка GitHub Pages проходят. Сгенерированный HTML отдельно проверен в изолированном Chromium на ширинах 320, 390, 430 и 1024 px, в том числе с отключённым JavaScript. Проверка в настоящем предпросмотре Telegram на iPhone остаётся за пользователем. Основной интерфейс в браузере не тестировался после последних правок по просьбе пользователя.

## GitHub Pages

1. Закоммить актуальные исходники и отправь их в ветку `main`.
2. В настройках репозитория открой Pages и выбери Source: GitHub Actions.
3. Workflow `Publish who travel` установит зависимости из публичного npm, выполнит `npm run build:pages` и опубликует только содержимое `out/`.

Сборка использует путь `/who_travel/`. Поездки и документы из браузера в сборку не входят. На адресе GitHub Pages отдельное хранилище: локальные поездки автоматически не переносятся. На GitHub Free для Pages нужен публичный репозиторий; приватный репозиторий поддерживается на соответствующих платных тарифах.

Если другая вкладка сохранила более новую версию данных, запись из старой вкладки блокируется с просьбой обновить страницу. Автоматического объединения изменений нет.
